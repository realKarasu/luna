Is Luna safe?

Yes. Luna is an ordinary Windows program that changes how your screens show colour, using settings Windows and your graphics driver already offer to every app. It never goes inside a game, never reads game memory and never talks to the internet. All of its code is open, so you can read it and build it yourself.

Open source, offline, no administrator rights

No injection, no access to other programs' memory, no driver or service, no account and no network connection.

What Luna never does

  • × Go inside games or other programs

    No DLL is loaded into another process and no code is started inside one. Luna has no way to reach into a game.

  • × Read or change game memory

    Luna never opens another program with memory rights, so it cannot read or write what a game keeps in memory.

  • × Touch game files

    Game folders, game settings files and anti-cheat files are never opened or edited.

  • × Block, change or record your input

    Every key and click is passed on to the game untouched. Nothing you type is stored, logged or sent.

  • × Install a driver or a service

    Luna runs as a normal app under your own account and never asks for administrator rights.

  • × Use the internet

    Luna itself makes no network requests: no login, no background updates, no statistics. It works the same with the network unplugged.

  • × Delete your files

    The only files Luna removes are old ones in your own Temp folder, and only when you press Clean.

What Luna does, and how

  • ✓ Gamma, brightness, contrast and RGB

    The display colour curve every screen has (SetDeviceGammaRamp), the same one night light tools and calibration apps use.

  • ✓ Hue, saturation, night vision and Ultra Zoom

    The Windows Magnification API, a full screen colour filter and zoom that is part of Windows.

  • ✓ Vibrance on NVIDIA and AMD cards

    The driver's own setting: digital vibrance through nvapi64.dll on NVIDIA, saturation through atiadlxx.dll on AMD. Both are loaded only from the Windows System32 folder, and only when that card is present. Intel and other cards get the full screen colour filter instead.

  • ✓ Finding your graphics card

    DXGI, the Windows graphics list, tells Luna which card drives each screen. Luna reads the card's name and maker, nothing else.

  • ✓ Binds and the look wheel

    A keyboard and mouse listener (low level hooks) tells Luna when a key goes up or down. Luna compares it with the keys you set and passes it straight on. Mouse movement is read only while the look wheel is open.

  • ✓ Crosshair and look wheel overlays

    Small see through windows that stay on top and ignore clicks. They draw pictures; they do not read the screen.

  • ✓ Optimizer

    Only the Windows settings you switch on, all in your own user settings (power plan, Game Mode, Game Bar recording, mouse acceleration and others). The old value is saved first, so Undo puts it back.

  • ✓ Settings and Start with Windows

    Plain JSON files in your AppData folder, and one entry in your own startup list, only if you turn it on.

Check it yourself

Read the code

Luna is MIT licensed. Every Windows call lives in a handful of small Rust files, one per feature, so the list below is easy to compare with the source.

Build your own copy

Install Rust and Node.js, then run these two commands in the Luna folder. The program you get is made only from the code you read.

npm install
npm run tauri build

Compare a download

In PowerShell you can print the fingerprint of any file and compare it with the one published with each release:

Get-FileHash .\Luna_x64-setup.exe

About the SmartScreen warning

Windows warns about new programs that are not signed with a paid certificate. It is not a virus alert. Choose More info, then Run anyway, or build Luna yourself.

Every Windows function that matters

The calls a cautious player may ask about, where Luna uses them, and what it does not use at all.

Luna, Windows functions in its own code
Source: src-tauri/src (Rust), one file per feature
Network: none. Administrator rights: never asked for.

Used, and why
  SetDeviceGammaRamp           colour curve of each screen (gamma, brightness, contrast, RGB)
  GetDeviceGammaRamp           remembers each screen's curve so it can be put back
  EnumDisplayMonitors          lists your screens and their positions
  GetMonitorInfoW              screen name, size and which one is the main screen
  CreateDCW                    opens a screen's colour curve, nothing else
  MagInitialize                starts the Windows colour filter and zoom
  MagSetFullscreenColorEffect  hue, saturation, night vision colours
  MagSetFullscreenTransform    Ultra Zoom
  CreateDXGIFactory1           which graphics card drives each screen (name and maker)
  LoadLibraryExW               nvapi64.dll (NVIDIA) or atiadlxx.dll (AMD), System32 only
  WM_DISPLAYCHANGE             notices new screens, resolutions and cards
  SetWindowsHookExW            keyboard and mouse listener for your binds, never blocks input
  GetAsyncKeyState             is a bound key still held down
  GetCursorPos                 where the mouse points while the look wheel is open
  SystemParametersInfoW        Optimizer: mouse acceleration, Sticky Keys, animations
  PowerSetActiveScheme         Optimizer: power plan
  RegSetValueExW               Optimizer tweaks and Start with Windows, your user only
  RegQueryValueExW             reads the old value first so Undo can put it back

Programs Luna starts
  powercfg.exe                 copies the High performance plan, only if Windows hides it
  explorer.exe                 opens your settings folder, only when you click it

Never called by Luna's own code
  CreateRemoteThread           start code inside another program
  QueueUserAPC                 run code inside another program's thread
  SetThreadContext             take over another program's thread
  WriteProcessMemory           write into another program
  ReadProcessMemory            read another program, such as a game
  VirtualAllocEx               reserve memory inside another program
  VirtualProtectEx             change another program's memory rights
  OpenProcess                  open another program at all
  GetKeyboardState             read the whole keyboard
  RegisterRawInputDevices      capture all raw input
  URLDownloadToFileW           download a file
  WinHttpOpen                  talk to a server
  CryptEncrypt                 encrypt files
  AdjustTokenPrivileges        raise its own rights
  CreateServiceW               install a service
  NtLoadDriver                 load a kernel driver
  DeviceIoControl              talk to a driver directly

Result: no injection, no memory access, no network, no driver.
